# Skills Dashboard

Build a single-file HTML page that visualizes every Claude Code skill you have installed — searchable, filterable, expandable. No server, no build step, no framework. Just open the HTML in a browser.

## What This Skill Builds

A **3-tab dashboard** as a single `.html` file:

| Tab | What it shows |
|-----|---------------|
| 我的技能库 | Card grid of every installed skill — name, source, description, expand to see all 7 dimensions |
| 什么是 Skill? | Educational deep-dive: the 7-dimension framework, annotated source code walkthrough of `brand-guidelines` SKILL.md, fill-in-the-blank template |
| 技能教程 | How to load existing skills (3 methods) and how to create new ones (7-step checklist + minimal template) |

The dashboard is warm-notebook themed (beige paper, grid lines, serif headings) and feels like a physical journal — deliberately avoiding "AI slop" aesthetics.

## Architecture: 3 Files, Zero Dependencies

```
your-dashboard-folder/
├── skills-dashboard.html          ← Open this in a browser
├── generate-skills-data.js        ← Node.js script (zero deps), run once, re-run when skills change
└── skills-data.js                 ← Auto-generated by the script. window.__SKILLS_DATA__ = {...}
```

**The data flow:**

1. `generate-skills-data.js` scans `~/.claude/skills/` and `.claude/skills/` directories, parses each `SKILL.md`'s YAML frontmatter and markdown body, applies enrichment data and auto-translation, and writes `skills-data.js`
2. `skills-dashboard.html` loads `skills-data.js` via a `<script>` tag and renders everything client-side with vanilla JS
3. When skills change, re-run the script and refresh the browser — the HTML never needs editing

The generation script has a **three-tier translation pipeline** for producing Chinese descriptions from English SKILL.md files:

1. `ENRICHMENTS` map — hand-written Chinese translations (best quality)
2. `PHRASE_DICT` — 50+ English→Chinese phrase pairs applied automatically (fallback)
3. Keep English original (last resort)

## Quick Start

**Step 1: Pick a folder** for the dashboard project. Anywhere works (`~/skills-dashboard/` or similar).

**Step 2: Copy the templates** from this skill into your folder:
- Copy `templates/skills-dashboard.html` → your folder
- Copy `templates/generate-skills-data.js` → your folder

**Step 3: Run the generation script:**
```bash
node generate-skills-data.js
```
This scans your actual skill directories and produces `skills-data.js`. No `npm install` needed — the script uses only Node.js built-ins (`fs`, `path`).

**Step 4: Open `skills-dashboard.html`** in a browser. That's it.

## Customization

### Styling

All colors live in CSS custom properties in the `:root` block at the top of the HTML:

```css
:root {
  --paper: #fef9f1;        /* Page background */
  --card: #fffcf5;         /* Card background */
  --terra: #d4866b;        /* Primary accent */
  --amber: #e8a840;        /* Secondary accent */
  --sage: #8fa87a;         /* Green accent */
  --font-display: 'Georgia', 'Noto Serif SC', serif;
  --radius: 12px;
  /* ... and more */
}
```

To change the entire visual direction:
- Edit these variables for quick color/type tweaks
- Invoke `frontend-design` for a complete redesign
- Invoke `theme-factory` to swap in a preset theme
- Invoke `brand-guidelines` to apply company brand colors

### Category Groups

The `CONFIG.categoryGroups` object in the HTML's `<script>` section maps filter chip labels to arrays of category names:

```javascript
categoryGroups: {
  '全部': null,                     // null = show all
  '创意设计': ['创意设计', '内容创作'],
  'API 开发': ['API 开发'],
  // Add or remove groups here
}
```

Categories are assigned by the `categorize()` function in `generate-skills-data.js`. Extend the `designSet`, `contentSet`, `toolSet`, `customSet` arrays with your skill names.

### Enrichment Data

The `ENRICHMENTS` map in the generation script provides high-quality Chinese translations for skills whose SKILL.md is in English. Each entry has 8 fields:

```javascript
const ENRICHMENTS = {
  'skill-name': {
    description: '简短中文描述：干什么 + 何时触发。',
    scenario: '应用场景',
    trigger: '触发关键词',
    features: '核心功能点',
    solves: '解决的痛点',
    steps: ['步骤1', '步骤2', '步骤3'],
    tools: ['工具A', '工具B'],
    verification: '验证问题'
  }
};
```

When you install a new English-language skill, add an entry here. If you skip this, the `PHRASE_DICT` auto-translation kicks in as a fallback.

### Builtin Skills

Skills without a `SKILL.md` file on disk (Claude Code system skills like `init`, `review`, `loop`) are defined in `BUILTIN_SKILLS` array. Each entry has the same structure as a parsed skill. Add new entries when Claude Code ships new system skills.

### Paths

The generation script auto-detects paths:
- **Windows**: `C:\Users\<name>\.claude\skills\`
- **macOS/Linux**: `/Users/<name>/.claude/skills/`
- **Project skills**: `./.claude/skills/` (relative to where you run the script)

If your setup is non-standard, edit `GLOBAL_SKILLS_DIR` and `PROJECT_SKILLS_DIR` at the top of the script.

### Source Badges

The `getSource()` function maps skill names to source labels. The `sourceClass()` function in the HTML maps labels to CSS classes. Extend both to add new source types:

```javascript
// In generate-skills-data.js:
function getSource(name) {
  if (name.startsWith('lark-')) return '飞书';
  if (name === 'my-custom-skill') return '自定义';
  return 'Anthropic';
}

// In skills-dashboard.html, add a CSS rule:
.source-badge.mytype { background: var(--sage-light); color: var(--sage); }
```

## Maintenance Workflow

Run `node generate-skills-data.js` whenever:
- A new skill is installed (cloned or created)
- A skill is removed
- A SKILL.md is edited
- Enrichment data is updated

The script prints a summary (`50 个技能, 16 个分类, 5 个来源`) so you can verify at a glance. The dashboard footer shows the generation timestamp — if the date looks old, re-run.

For automatic refresh: tell Claude "When I report adding/changing/removing a skill, auto-run the generation script and remind me to refresh the browser." The original project had this saved as a memory.

`skills-data.js` can be added to `.gitignore` since it is regenerated from source.

## The 7-Dimension Framework

Every well-written SKILL.md answers 7 questions. The dashboard uses this framework to display each skill's capabilities:

| # | Dimension | Core Question | Where in SKILL.md |
|---|-----------|---------------|-------------------|
| 1 | 元数据 (Metadata) | Who am I? When to trigger? | YAML frontmatter (`name` + `description`) |
| 2 | 边界 (Boundary) | What do I handle? What do I NOT handle? | First body paragraph (overview/scope) |
| 3 | 流程 (Process) | What are the steps? Input→Action→Output→Decision? | `## Execution Steps` |
| 4 | 工具 (Tools) | What concrete resources? Files, values, commands? | `## Color Palette` / `## Tools` / data tables |
| 5 | 容错 (Fallback) | What happens when something fails? | `## Fallback Strategy` / inline if→else |
| 6 | 评测 (Evaluation) | Did I follow the spec? Yes/no checklist? | `## Verification Checklist` |
| 7 | 验证 (Verification) | Does the output actually work in the real world? | `## Post-Output Validation` |

Dimensions 1-2 define **identity and scope**. Dimensions 3-5 define **behavior**. Dimensions 6-7 define **quality gates**.

A skill missing dimension 2 fires in wrong contexts. Missing dimension 5 fails silently. Missing dimension 7 produces output that *looks* right but is broken.

Read `references/7-dimensions.md` for the full explanation with brand-guidelines examples and common mistakes for each dimension.

## The Iterative Refinement Process (Meta-Lesson)

This dashboard itself went through 8+ iterations before reaching the current version:

1. **Initial prototype** — 6 dimensions, basic expandable cards
2. **Chinese translation** — All descriptions translated via ENRICHMENTS map
3. **Auto-translation fallback** — PHRASE_DICT for future English skills
4. **7th dimension added** — Verification (评估验证) separated from Evaluation (评测)
5. **Tab 2 rewritten** — Full annotated `brand-guidelines` source code walkthrough with plain-language translations under every code block
6. **Dimension ordering fixed** — 3(流程)→4(工具)→5(容错) corrected
7. **Auto-refresh mechanism** — Memory-based trigger to re-run script on skill changes
8. **Final polish** — Card animations, search, category tabs, warm notebook theme

The meta-lesson: building a good skill dashboard is itself a skill-engineering exercise. The generation script is the engine — invest time in enrichment data and categorization logic, and the dashboard improves automatically. Iteration is natural: as your skill collection grows, you will refine categories, enrichments, and the script itself.
